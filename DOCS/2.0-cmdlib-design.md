# WinuxCmd 2.0 命令库化设计稿 — 显式 IO 的库形态命令接口（#1488 试点稿）

状态：设计稿 + 单命令试点（`pwd`），随 draft PR 提交评审。本稿定义库形态命令的
接口形状、ABI 面取舍、宿主调用约定、机械替换步骤，以及从 #1487 三个坑推出的
硬性设计约束（禁符号 lint）。清点扫描（#1488 第一步的 inventory 表）另行推进，
本稿 §2.2 与 §6 的列定义可直接被 inventory 表复用。

边界（与 #1488 一致）：

- 不接入主线构建，不影响 1.x C++ 命令集的维护与发版（1.2.0 按既定序先行）。
- 库形态命令进产品仍受 niubash#727 翻转门约束；本设计只是把前置条件里的
  「IO 习语收敛」从修补升级为重写。

## 1. 问题：exe 形状的代码为什么进不了宿主进程

#1487 实证（niubash#727 门①③），根因全部落在 DLL 侧代码形状 — applet 是按
独立 exe 写出来的，隐式依赖进程级状态，塞进宿主进程后 `SetStdHandle` 接不齐：

| 坑 | 代码形状 | 位置 |
|---|---|---|
| ① CRT fd 绑死 | `/MT` CRT 在 DLL 加载时把 fd 0/1/2 绑到当时的 stdio，宿主之后替换句柄，CRT 缓冲照旧 | FFI 路线通病（#1487 评估） |
| ② `std::cin`/`std::cout` 直写 | iostream 对象加载期构造并绑 fd，输出不达注入句柄（`sort words.txt > o.txt` 结果喷终端、o.txt 为空） | 同上 |
| ③ console 句柄缓存 | `thread_local HANDLE g_cached_stdout/g_cached_stderr` 首次 `GetStdHandle` 后缓存，靠人肉调 invalidate 失效 | `src/utils/console.cppm:61-99` |

外加缺陷 B（dispatch 期间不轮询取消，`src/ffi/ffi.cpp:327-329` 只在 dispatch
前查一次）：不是 IO 接线问题，而是「命令循环没有检查点」的结构问题，库形态
接口必须一并解掉（§2.2 `cancel_flag`）。

结论：修补 = 给每条隐式通道加失效钩子，通道数随命令习语增长，永远接不齐；
治本 = **让隐式通道不存在** — 命令拿到的一切（流、env、cwd、取消信号）都是
显式参数。

## 2. 库形态命令的接口形状

### 2.1 C ABI 签名

```c
typedef struct WcmdIoCtx WcmdIoCtx;   /* 不透明指针过边界，定义见 §2.2 */

int32_t wcmd_abi_version(void);       /* 宿主加载后先校验，拒绝不匹配的库 */
int32_t wcmd_<name>(const WcmdIoCtx *ctx);
```

- 一个命令 = 一个导出函数，命令名与符号一一对应（`wcmd_pwd`、`wcmd_sort`…），
  与现 tiers.tsv 路由行同粒度。
- 返回值即命令退出码（0–125 为 GNU 域；126 为「库内 panic」宿主约定，见
  §2.4）。返回码语义是 exit status 本身，不是 wait status，宿主直接映射 `$?`。

### 2.2 `WcmdIoCtx`（ABI v0，试点版）

| 字段 | C 类型 | 语义 |
|---|---|---|
| `stdin` / `stdout` / `stderr` | `void*`（Win32 HANDLE） | 借用：仅调用期间有效，被调方禁止 `CloseHandle`、禁止缓存到调用期之外（含 thread_local/静态）。`NULL` = 该流未提供（命令按需报错或忽略） |
| `env_block` | `const char*` | UTF-8 `"K=V\0…\0\0"` 双 NUL 结尾环境块，借用只读。替代一切 `GetEnvironmentVariable*` / `std::env::`。选 UTF-8 而非 Windows UTF-16 块：argv/cwd/env 统一一种编码过边界，且 WinuxCmd 内部本就以 UTF-8 为主（`pwd.cpp` 的 `wstring_to_utf8` 路径） |
| `cwd` | `const char*` | UTF-8 NUL 结尾物理工作目录，借用只读。替代 `GetCurrentDirectoryW`。宿主契约：传「已解析符号链接的物理路径」（`pwd -P` 语义） |
| `argc` / `argv` | `int32_t` / `const char**` | UTF-8，`argv[0]` = 命令名 |
| `cancel_flag` | `const uint32_t*` | 宿主拥有的取消标志，非 0 = 请求尽快终止。借用只读。长循环/大块读写检查点必须轮询（#1487 缺陷 B 的结构解：检查点在命令循环内，而不是 dispatch 外）。`NULL` = 宿主不支持取消 |

硬规则（§6 lint 强制，违例即测试红）：

1. 一切字节 IO 只经 `ctx` 的三个句柄；禁止查询或写进程级 stdio。
2. 一切环境读取只经 `env_block`；一切 cwd 只经 `ctx->cwd`。
3. 句柄借用制：不关闭、不复用、不跨调用缓存。
4. `exit()`/`abort()` 禁止 — 以返回码结束。
5. panic 在边界内收（§2.4），不得穿越 FFI 边界。
6. 不假设调用线程与 TLS，不假设 locale（文本处理显式传参），函数无全局状态
   （可重入，同进程并发调用多个命令合法）。

### 2.3 写入语义

- 句柄可能是 pipe / 文件 / console 任意一种：库侧统一按字节流写
  （`write_all` 语义），console 转换是句柄自身的事。宿主注入什么，输出就去
  哪 — #1487 缺陷 A（`sort > o.txt` 数据丢失）的直接反面。
- 无缓冲残留：命令返回前，已声明写出的数据必须全部写达句柄；库不得引入跨
  调用的用户态缓冲。

### 2.4 panic 与返回码

Rust panic 默认打印到进程 stderr — 这本身就是一条隐式通道，必须在边界内一并
摘除：边界函数 `catch_unwind` + 临时静默 panic hook（调用前 `take_hook` 换静默
hook，返回前恢复）。panic → 经 `ctx->stderr` 写一行 `wcmd: internal panic in
<name>` 诊断 + 返回 126。选 126：GNU 域内语义近邻（「找到了但无法执行」），
且 exe 世界里对应进程崩溃，宿主本来就要特殊处理，不会与正常退出码混淆。

## 3. cdylib vs 静态库 — ABI 面取舍

关键不变量：**两种形态共享同一个 C 头（§2.2），ABI 面完全相同**；取舍只影响
部署，不影响命令代码。命令代码永远只认 `WcmdIoCtx`。

| | cdylib（如 `winuxcmd_cmd.dll`） | Rust 静态库链进宿主 |
|---|---|---|
| 部署 | 宿主 `LoadLibrary` + tiers 路由热加载；按命令渐进、可回滚、可独立发版 | 换一个命令 = 重链宿主、重发宿主版本 |
| 版本 | `wcmd_abi_version()` 运行期协商，不匹配拒绝加载 | 编译期绑死 |
| 调用开销 | 每命令一次 `GetProcAddress`，之后同 C 调用 | 零 |
| Rust 运行时 | 每个 cdylib 自带一份静态 Rust std/allocator | 与宿主共享（宿主须是 Rust 或链 Rust staticlib） |
| 风险面 | 进程内形态，与 #1487 同类 — 上线仍受 niubash#727 门 | 同左 |

### 3.1 只传句柄/缓冲，不传环境状态（硬规则）

允许过边界的类型：整数/浮点/布尔/枚举的 `#[repr(C)]` 化形态，及裸指针指向
（a）Win32 HANDLE 值、（b）借用期内只读的字节缓冲（env/cwd/argv）、（c）POD
结构字段。

禁止过边界：`FILE*`、iostream 对象、Rust `&str`/`&[T]`/`String`/`Box`（布局
与所有权不跨边界）、一侧分配另一侧释放的堆指针、errno/locale 假设。

理由：坑①（CRT fd）与坑②（iostream）的教训是「带运行时状态的对象过边界 =
把那侧的进程状态也拖过边界」。句柄与借用缓冲没有任何加载期/线程期状态，
宿主 `SetStdHandle` 与否、CRT 初始化与否都不影响它们。

### 3.2 版本协商

宿主流程：`LoadLibrary` → `wcmd_abi_version()` 不匹配则卸载并回退 spawn。
ABI 变更（加字段只加尾部 + 版本 +1；宿主按版本判读）。试点从 0 开始。

## 4. 宿主侧调用约定

```
1. 路由命中库形态命令（tiers.tsv 行标注 lib 形态）
2. 解析 wcmd_<name>，校验 wcmd_abi_version()
3. 组装 IO：重定向的管道/文件句柄；无重定向时由宿主把「进程默认」
   翻译成显式句柄再注入 — 这个翻译只发生在宿主侧，库永远不做
4. 组装 env_block（宿主 env 继承 + 命令前缀赋值改动）、cwd（宿主
   物理 cwd）、argv、cancel_flag
5. 在工作线程调用 wcmd_<name>(&ctx)；需要取消时置 cancel_flag
   （dispatch 线程不必等待，也不依赖回调时序）
6. 调用返回后：关闭自己创建的句柄端，读取对端，返回码映射 $? / 子进程语义
```

线程模型：宿主在专用线程或线程池调用；库侧无亲和性要求（§2.2 规则 6）。

## 5. 机械替换步骤清单（每命令固定 8 步）

1. 查 #1462 Oracle 审计行与 GNU 源码 owner，记录 `file:line`。
2. 清点该命令隐式状态：`io_idiom` / `global_state` / `exit_usage` 三列
   （inventory 表）。
3. Rust 实现：全部 env/cwd/stdio/取消经 `ctx`；parity 记录逐条继承 #1462
   审计结论，不清零重来。
4. 过 §6 禁符号 lint（零容忍）。
5. 差分门：lib 版 vs exe 版逐字节等价 + GNU 三方对照 + 既有差分/回归测试。
6. tiers 切换该命令到库形态，**同 PR 删除 C++ 实现**（不双轨，#1488 已裁定）。
7. 用户可见消息走 i18n 键（AGENTS.md I18N 同步规则，含 winuxcmd-i18n 仓同
   任务更新与版本 bump）。
8. inventory 表更新该命令 replace_wave 状态，#1488 回帖记录。

## 6. 硬性设计约束：从 #1487 三坑到 lint

| #1487 坑 | 库形态禁令 | lint token |
|---|---|---|
| ① CRT fd 绑死 | 禁 CRT stdio | `printf` `fprintf` `fwrite` `fopen` `_get_osfhandle` |
| ② cin/cout 直写 | 禁 iostream 与 Rust 进程 stdio | `std::cin` `std::cout` `std::io::stdout` `std::io::stderr` |
| ③ console 句柄缓存 | 禁一切进程句柄/环境/cwd 查询与改动 | `GetStdHandle` `GetCurrentDirectory` `GetEnvironmentVariable` `std::env::` `SetStdHandle` |
| 进程穿透 | 禁 exit 与子进程生成 | `std::process::exit` `std::process::Command` |

lint 实现（双层，同一张 token 表）：

- **可执行 lint（本 PR 落地）**：
  `experimental/cmdlib-pilot/tests/lint_banned_io.rs` — 一个普通 cargo 测试，
  扫描库源码（剥 `//` 行注释后）匹配禁符号表，违例即红并列出
  `文件:行 token 原因`。宿主/harness 源（`src/host/`）豁免 — 它们正是把
  进程状态翻译成显式 ctx 的一侧。机械替换步骤 4 必含此测试；产品化后随
  主线 CI 跑。
- **CI grep（产品化时）**：同一张表进 CI 脚本，防止绕过 cargo test 直接触
  红线；白名单文件 = 宿主/harness。

为什么 grep 式而不是自定义 clippy lint：要同时覆盖 C++ 与 Rust 两族（2.0 过渡
期双语言并存）、维护成本最低、一处定义两处用；后续可叠加
`#![deny(clippy::disallowed_methods)]` 作 Rust 内双保险。剥注释后匹配，注释里
解释禁令时可以直书 API 名。

## 7. 试点（本 PR）

`experimental/cmdlib-pilot/`（独立 cargo 工程，不进 CMake 主线，不影响任何
现有 target）：

- 库：`wcmd_pwd`（cdylib + rlib + staticlib 三形态同源），移植
  `src/commands/pwd.cpp` 管线 — `-L`/`-P` 选项、`POSIXLY_CORRECT` 存在性测试
  默认（pwd.cpp:62-65，[GNU] pwd.c:331）、PWD 校验链（绝对路径/无 `.` 与
  `..`/存在/等价于 cwd，pwd.cpp:99-177）、物理路径 canonicalize（pwd.cpp:123-150）、
  非 option 操作数告警（pwd.cpp:209-211）。
- 宿主 demo：`cmdlib-pilot-host.exe` **不链接库**，`LoadLibraryW` 加载 cdylib
  （真实宿主形态），`CreatePipe` 造管道，把写端注入 ctx 作为 stdout/stderr，
  注入**假 cwd**（临时目录 ≠ 宿主进程 cwd）与假 `PWD` 环境块。
- 静态形态证明：`tests/static_link_pwd.rs` 以 rlib 直链 `wcmd_pwd`，注入一个
  **文件句柄**（`= sort > o.txt` 的字面形态），断言输出落在文件里。
- 验证命题（= #1487 缺陷 A 的反面）：
  1. pwd 输出进注入管道，宿主进程 stdout 零泄漏（宿主输出重定向到文件后，
     非 `[host]` 前缀行数为 0）；
  2. 输出内容 = 注入的 cwd 而非宿主进程 cwd（证明无 `GetCurrentDirectoryW`
     逃逸）；
  3. `-L`/`POSIXLY_CORRECT`（含存在但为空）读的是注入 env 块（证明无
     `GetEnvironmentVariableW` 逃逸）；
  4. stderr 走注入的 stderr 句柄。
- 明确不做（留机械替换步骤）：接主线构建与 wpm 打包、i18n 接线（试点消息
  硬编码英文，步骤 7 补）、完整 getopt 错误面 parity（无效选项路径标记
  SIMPLIFIED，差分门步骤 5 收口）。
