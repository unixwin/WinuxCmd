## 2. PR-1 · packaging fix

### 2.1 现象

归档（`.zip`/`.7z`/`.tgz`）解包后，按 README/Release notes 的官方步骤：

```
cd ...\WinuxCmd-1.2.1-win-x64\usr\bin
.\create_links.ps1
wpm: links created=172 unchanged=0 stale_removed=0 failed=0
dir *.exe            → winuxcmd.exe, winuxcmd-shim.exe   （只有 2 个）
dir /s /b *.exe      → 172 个全在 usr\bin\usr\bin\
```

命令一个没少，但**一个也不在 PATH 上**；同时 `usr\bin` 下被建出
`bin\ dev\ etc\ opt\ usr\ var\` 一套布局目录。

### 2.2 根因

1. `Get-Location` 返回 `PathInfo`，**没有 `.Name`/`.Parent`**（PS 5.1 + 7.7 实测为空），
   `scripts/create_links.ps1` 的"从 usr\bin 折回 root"分支恒假 → `--root` 收到
   `usr\bin`。该分支由 `3e1090e1`（2026-08-15）引入。
2. `wpm` 对显式 `--root` 不做 bin 折叠（`default_root()` 从 exe 路径推断时有这套
   折叠），`canonical_bin_dir(root) = root/usr/bin` → 嵌套。

安装器（ISS 传 `{app}`）与 niubash（传 `$NIHOME`）都不受影响，所以 CI 一直绿。

### 2.3 diff

`scripts/create_links.ps1`：

```diff
 $winuxCmdPath = Get-WinuxCmdPath
-$binDir = Get-Location
-$root = if ($binDir.Name -eq "bin" -and $binDir.Parent.Name -eq "usr") {
-    $binDir.Parent.Parent
-} else {
-    $binDir
-}
+# `Get-Location` returns a PathInfo, which has no `.Name`/`.Parent` members -
+# reading them yields $null, so the old test was always false and $root stayed
+# the bin directory itself. wpm then created usr\bin *inside* usr\bin and the
+# 172 entry links landed one level too deep (the archive's documented first-run
+# step was broken from 3e1090e1 on; the installer was unaffected because ISS
+# passes {app} explicitly). Work on real path strings.
+$binDir = (Get-Location).ProviderPath
+$root = if ((Split-Path -Leaf $binDir) -eq "bin" -and
+            (Split-Path -Leaf (Split-Path -Parent $binDir)) -eq "usr") {
+    Split-Path -Parent (Split-Path -Parent $binDir)
+} else {
+    $binDir
+}
```

`src/commands/wpm.cpp`：把 `default_root()` 的折叠抽成 `fold_bin_dir()`，
显式 `--root` 也走一遍：

```diff
+/// Fold a directory that names a bin directory to the install root above it.
+/// ...
+auto fold_bin_dir(fs::path dir) -> fs::path {
+  if (dir.filename() != L"bin") return dir;
+  auto parent = dir.parent_path();
+  if (parent.filename() == L"usr") return parent.parent_path();
+  if (parent.filename() == L"local" &&
+      parent.parent_path().filename() == L"usr") {
+    return parent.parent_path().parent_path();
+  }
+  return parent;
+}
+
 auto default_root() -> fs::path {
   auto exe_dir = current_exe_path().parent_path();
-  if (exe_dir.filename() == L"bin") { ... }
-  return exe_dir.empty() ? fs::current_path() : exe_dir;
+  if (exe_dir.empty()) return fs::current_path();
+  return fold_bin_dir(std::move(exe_dir));
 }
```

```diff
-  opts.root = root.empty() ? default_root() : fs::path(root);
+  opts.root = root.empty() ? default_root() : fold_bin_dir(fs::path(root));
```

只折 `bin` 结尾的目录，真正的 root 名不会被改写（`--root C:\tools\usr` 不动）。

`tests/unit/wpm/wpm_unit_test.cpp` 新增
`wpm_links_rebuild_folds_a_bin_directory_to_the_root`：以 `usr\bin` 作为
`--root` 跑 rebuild，断言 `usr\bin\wpm.exe` 存在且 `usr\bin\usr\bin` 不存在。

### 2.5 风险

- 折叠只认 `bin` 结尾目录：一个"真的叫 bin 的 root"会被折成父目录。这种 root
  在 Windows 上必然违背本仓 `<root>\usr\bin` 约定，且 `default_root()` 早就这么
  处理了 exe 路径，行为一致。
- 对 `--root <root>`（正常形态）零影响：`fold_bin_dir` 原样返回。

## 4. PR-3 · CI 硬化（wpm-source index + edition census）

### 4.1 `update-wpm-source-index` 恢复（已改，见工作树）

设计要点（根因分析见审计 §6）：

```yaml
needs: [build-windows, release]
if: >-
  always() &&
  (github.event_name == 'workflow_dispatch' ||
   (github.ref_type == 'tag' && startsWith(github.ref_name, 'v')))
```

- `always()` + 显式 gate：上游红时 job **变红并给出可操作信息**，不再静默
  skipped（v1.2.0 首跑就是这样无声丢索引）。
- 版本号自取（`${GITHUB_REF#refs/tags/v}` 或 `workflow_dispatch.inputs.version`），
  不再依赖 `needs.release.outputs.version`。
- 两条下载路径：
  - tag 运行 → 本 run 的 artifacts（就是随 release 发布的那份字节）；
  - `workflow_dispatch` + `version` → **从已发布 Release 下载资产**（修复旧版本
    时必须索引"发出去的那份"，不是当前 main 的构建）。
- `dry_run` 输入：算一遍索引并写 `$GITHUB_STEP_SUMMARY`（sha256/尺寸/URL），
  然后 `git checkout -- index.json` 不推。
- PR 步骤变严：`--jq '.[0].url // empty'`、URL 必须匹配
  `https://github.com/unixwin/wpm-source/pull/*`、merge 后 `gh pr view --json state`
  必须 `MERGED`，否则 job 红。

**恢复验证（发布后不需要重打 tag）**：

```bash
gh workflow run build-winuxcmd.yml -f version=1.2.1 -f dry_run=true
# 期望：summary 里出现 winuxcmd 1.2.1 的 sha256/size/url，且 notice "nothing pushed"
gh workflow run build-winuxcmd.yml -f version=1.2.1
# 期望：走 "already matches" 早退（索引已是 1.2.1），不产生空 PR
```

> 注意：`workflow_dispatch` 跑整个 workflow 会重跑 build-windows（几分钟）。
> 若只想修索引，可后续把该 job 拆成独立 workflow（`wpm-index.yml`），
> 本 PR 不拆，保持 diff 小。

### 4.2 edition census（**未落代码，建议单独 PR**）

在 default / full 两个 leg 各加一步，用二进制自己声明的名字做等式，
不硬编码 172/178：

```powershell
$bin = ".\usr\bin\winuxcmd.exe"
$plan = & $bin wpm links rebuild --root . --dry-run |           # "link <t> -> <s>"
        ForEach-Object { if ($_ -match '^link (.+) -> ') { Split-Path -Leaf $matches[1] } }
& $bin wpm links rebuild --root . | Out-Null
$actual = Get-ChildItem .\usr\bin\*.exe -Name |
          Where-Object { $_ -notin @('winuxcmd.exe','winuxcmd-shim.exe') }
if (Compare-Object ($plan | Sort-Object) ($actual | Sort-Object)) { throw "edition census mismatch" }
$fullOnly = @('[.exe','false.exe','kill.exe','test.exe','time.exe','true.exe')
$present  = $actual | Where-Object { $_ -in $fullOnly }
if ('${{ matrix.edition }}' -eq 'default' -and $present) { throw "default ships full-only entries: $present" }
if ('${{ matrix.edition }}' -eq 'full' -and $present.Count -ne 6) { throw "full is missing full-only entries" }
if ($actual -match '^(jq|link)\.exe$') { throw "retired legacy name materialized" }
```

价值：把本次一次性审计变成每次 CI 都验的等式（含未来 grep wire 后的
`egrep`/`fgrep` 风险）。

### 4.3 `build-installer.ps1`（**未落代码**）

if ($PackageArch) { $buildScriptArgs += @("-CMakeExtraArgs", "-DWINUXCMD_PACKAGE_ARCH=$PackageArch") }
