# WinuxCmd 2.0 Migration Guide (1.x → 2.0.0)

> **Draft at the 2.0 freeze (2026-11-14, `origin/main` = f0cf6b17).** Every
> claim below is tied to a gate record or an issue. Re-verify the numbers at
> the release commit; the tag may include wiring waves that landed after this
> snapshot.
>
> **中文摘要**：2.0 把命令实现从 C++ 主体机械替换为 **rust2 库形态**
> （显式注入 IO、无进程全局状态、返回状态码），命令集、命令名、
> `--help` 品牌文案、multicall/edition 机制、WPM 都**不变**。变化分三类：
> ① 1.x 的私有扩展（`echo -u/-r`、`fmt -m/-P/-x/-X/-T`、`fold -c`、
> `numfmt --unit-separator/-M/-l` 等）按 GNU 退役；② 1.x 与 GNU 不一致
> 的行为被修正（详见逐命令表）；③ 尚未接线的命令在 2.0.0 里**行为不变**，
> 它们的 GNU 差异是 1.x 遗留 bug，按 issue 跟踪。遇到新差异请按 §8 报告。

## 0. How to read this guide

- **1.x** means WinuxCmd 1.2.1 (the last 1.x release) as recorded by the
  three-way gate (`r=c` column: new-vs-old exe rc + stdout).
- **2.0.0** means the release this guide ships with. The per-command table
  distinguishes three states:
  - **wired** — the product path is rust2; differences below are verified.
  - **ready** — the Rust library is on main and the differential gate is
    green, but the product still dispatches to the 1.x C++ body; there is
    no user-visible 2.0 change *yet*.
  - **1.x** — still the 1.x implementation; 2.0.0 does not change it.
- Evidence abbreviations: **GR** = `rust2/GATE-REPORT.md` (the wave section
  that measured the rows), **INV** = `DOCS/2.0-inventory.tsv`, **GH** = a
  GitHub issue number.

**Data sources and one gap.** The gate ledger (`target/gate/ledger.tsv`,
gitignored) is the primary `r=c` record; the committed narrative is GR.
The oracle-audit board (`DOCS/oracle-audit/`) is **not on `origin/main`** —
it is held in the `wc-oracle` lane's local worktree — so this guide uses
the 19 `compat-gap` issues **#1639–#1657** (plus #1670/#1672/#1675) as the
audited-difference source. At release, cross-check the board and replace the
issue anchors with its line anchors where they differ.

## 1. The short version

1. **Command set, names, options surface, help text, editions, WPM: unchanged.**
   2.0 replaces *implementations*, not the interface. `winuxcmd <cmd>` and a
   multicall entry link resolve exactly as in 1.x.
2. **2.0 is GNU-truer where 1.x had invented behavior.** Private options
   retire (§3); recorded 1.x deviations are corrected (§4, §5).
3. **A wired command never falls back to C++.** There is no dual track: if
   the Rust library is not built, the command is absent from that build
   (the CMake `WINUXCMD_ENABLE_RUST2` contract). Official builds ship Rust.
4. **Windows platform subsets remain.** NTFS has no POSIX mode bits or
   numeric uid/gid; ownership changes need OS rights; symlink creation needs
   Developer Mode or elevation; SELinux does not exist. These are documented
   subsets, not 2.0 regressions (§6).
5. **Scripts that depended on a retired 1.x extension must change**; scripts
   that used GNU syntax get more GNU-faithful output, not less.

## 2. What a 2.0 binary is

```
winuxcmd.exe  (one image, one CRT)
├── C++ front end        registration metadata, dispatcher, option policy,
│                        help/version interception, wpm, retained faces
├── rust2_bridge         the only C++ that touches the ABI
├── winuxcmd_ffi         C ABI v2: winuxcmd_run / winuxcmd_run_stream
└── winux-cmds           library-form commands (Io, Ctx, CmdResult)
    └── winux-core       Ctx/EnvSource/HostServices/path/regex seam
```

- **Library form**: `pub fn <cmd>_cmd(args: &[OsString], io: &mut Io, ctx: &Ctx) -> CmdResult`.
  No command calls `exit()`, touches process stdio, reads the process env,
  or keeps process-global mutable state.
- **Injected IO**: the host passes bytes in and receives byte buffers out;
  a pull callback (`winuxcmd_run_stream`) provides streaming stdin. Rust
  never opens a CRT fd or a console handle.
- **Multicall**: dispatch is by `argv[0]`; entry links are real hardlinks
  to `winuxcmd.exe` (never launchers). Editions only decide which entry
  links are materialized.
- **Editions**: `default` and `full` are the same source; `full` adds entry
  links for the shell-builtin shadow names (`[`, `env`, `false`, `kill`,
  `test`, `time`, `true`) and carries the `-full` asset suffix. The
  default edition is the wpm-indexed one.
- **I18N**: runtime messages carry stable keys and English fallbacks in
  source; translations arrive through the host (`WINUX_LANG`) from the
  separately published catalog. Untranslated builds are English-only.
- **Retained C++ faces**: `grep -P` (PCRE2; decision doc
  `DOCS/2.0-regex-engine-decision.md` §6), the dispatcher/registration
  shell, WPM, and the `!<fifo>` named-pipe bridge. A split-engine command
  routes its non-retained face to Rust and the retained face to C++ (grep
  does this per invocation; `egrep`/`fgrep` always route to Rust).

## 3. Retired 1.x extensions

All of these were WinuxCmd-only spellings. GNU rejects them (usually
`invalid option`, exit 1) or treats them as data. The 2.0 rule is: **follow
GNU, and do not let the dispatcher reject what GNU would accept as data.**

| 1.x extension | GNU basis | 2.0 behavior | Anchors |
|---|---|---|---|
| `echo -u`, `echo --upper` | coreutils `echo.c` scans only `-n`, `-e`, `-E` as leading options; `echo -u hello` prints `-u hello` | prints `-u hello` as data (rc 0). Help/man still mentions the spelling for continuity; as a flag it can never reject argv | GR wave6; `src/commands/echo.cpp` |
| `echo -r N`, `echo --repeat N` | `echo.c` has no repeat concept | `-r`/`--repeat` are data; the dispatcher no longer int-validates the following token (`echo -r x` → `-r x`, rc 0) | #1621; GR wave6 |
| `fold -c`, `fold --characters` | POSIX/GNU fold options are `-b/--bytes`, `-s/--spaces`, `-w/--width` only | `invalid option -- 'c'`, rc 1 | GR wave3a |
| `fmt -m`, `fmt --preserve-headers` | GNU fmt has no mail-header mode | `invalid option`, rc 1 | GR wave3a |
| `fmt -P`, `fmt --skip-prefix` | not a GNU fmt option | `invalid option`, rc 1 | GR wave3a |
| `fmt -x`, `fmt --exact-prefix` | not a GNU fmt option | `invalid option`, rc 1 | GR wave3a |
| `fmt -X`, `fmt --exact-skip-prefix` (the "awk-like `-X`" approximation) | not a GNU fmt option; GNU only has `-c/-p/-s/-t/-u/-w/-g` | `invalid option`, rc 1 | GR wave3a |
| `fmt -T`, `fmt --tab-width` | GNU fmt's tab width is a compile-time 8; no option | `invalid option`, rc 1 | GR wave3a |
| `numfmt --unit-separator` | coreutils 9.4 `numfmt.c` option table has no such long option | `unrecognized option`, rc 1 | GR wave3b; `numfmt.rs` module doc |
| `numfmt -M`, `numfmt -l` | no such shorts in GNU numfmt 9.4 | `invalid option`, rc 1 | GR wave3b |
| `numfmt` input suffixes `Z/Y/R/Q` | GNU 9.4 rejects these suffix letters (the 1.x parser accepted them) | rejected like GNU 9.4; `K/M/G/T/P/E` and `KiB`-family stay | GR wave3b |

**Retained on purpose (not GNU, but kept for compatibility):**

| spelling | why it stays |
|---|---|
| `realpath -E` | WinuxCmd extension (`all components but the last must exist`); a documented superset. GNU has no `-E`. |
| `rev -0` | Matches the oracle: util-linux 2.39.3 accepts `-0` (undocumented). |
| `hostname -i/-I/-s` | Matches the Debian hostname 3.23 oracle (net-tools spellings), not coreutils. |

**Do not port forward:** a retirement applies to the *option*, not to the
data. Rewrite scripts as:

```diff
- echo -r 3 "---"
+ for i in 1 2 3; do echo "---"; done
- echo --upper ok
+ echo ok        # uppercase with tr if you actually need it
- fmt -X -w 72 file
+ fmt -w 72 file
```

## 6. Platform subsets that are NOT 2.0 regressions

| area | what Windows cannot do | what 2.0 does | Anchor |
|---|---|---|---|
| POSIX mode bits | NTFS has no `rwx`/setuid/setgid/sticky storage | parses the full GNU mode grammar; persists owner-write as the read-only attribute; other bits live in the in-memory model; `-R` uses GNU fts preorder and refuses filesystem roots | GR wave1 deepening |
| Ownership | no POSIX uid/gid; group changes need `SeRestorePrivilege` | real owner change where the OS grants `WRITE_OWNER`; OS denial maps to GNU's `Operation not permitted` rc 1; numeric ids are validated no-ops | GR wave1 deepening |
| Symlinks | creation needs Developer Mode/admin | `ALLOW_UNPRIVILEGED_CREATE` attempted; otherwise documented refusal (no silent copy unless opted in) | GR wave3a |
| `df` inodes | NTFS reports no inode counts | inode columns 0 / `IUse% -` (documented deviation); 12-column `--output` model implemented | GR wave1; #1657 open for column widths |
| SELinux (`chcon`, `runcon`, `ls -Z`) | no SELinux | capability probe; GNU non-SELinux shapes (`?`, rc 0) where the oracle has them | #1643; GR wave5 |
| FIFO / device nodes | no POSIX FIFOs; named-pipe bridge | `!<fifo>` marker contract through the C++ `file_io` layer | #1038; GR wave5/wave6 |
| Terminal metadata | library cannot see console-ness through injected IO | input class is injected (`tail::StdinMeta`); registry defaults to pipe; driver composes the real class | GR tail follow; `rust2/README.md` |
| Time zone | no `TZ` handling in some paths | `touch` uses `SetFileTime` + DST-aware conversion; `stat` TZ is an open gap | #1655 |
| Broken pipe | no POSIX SIGPIPE | output write error surfaces as the host status (141 by policy); per-command overrides (grep 2, xargs 125) are pending the host-v4 ownership ruling | #1487; GR xargs |
| Locale | no full locale database | `LC_ALL=C` byte model is the gate domain; `#1549` locale-database simulation is the 2.0 item | `DOCS/2.0-MASTER-PLAN.md` §0 item 6 |

## 7. What is deliberately unchanged

- **176 commands** (the multicall set), their names, and their option
  registration surface.
- **`--help` / `--version` text** remains the WinuxCmd-branded dispatcher
  output for the wired commands (the pilot's GNU-driver help text is not the
  product surface). Sole-argument interception rules match 1.x.
- **Editions and entry links**: default vs full, the `-full` suffix, and the
  wpm-indexed default artifact.
- **WPM** (package manager, `wpm` command) and the package contracts in
  `AGENTS.md`.
- **Cygwin/MSYS bridging commands** (`cygpath`, `d2u`, `u2d`, `dos2unix`,
  `unix2dos`, `regtool`) — these are Windows-specific by design and have no
  GNU oracle.
- **`link` does not exist and will not be added** (MSVC `link.exe` collision;
  `WINUXCMD_BANNED_COMMANDS`).

## 8. Reporting a difference

1. Pin the oracle: WSL GNU coreutils 9.4 (or the command's upstream:
   findutils 4.9.0, util-linux 2.39.3, Debian hostname 3.23), `LC_ALL=C`,
   `TZ=UTC`.
2. Give the exact argv, stdin bytes, cwd shape, and the three outputs
   (GNU / WinuxCmd 1.2.1 / WinuxCmd 2.0) with exit codes.
3. File it with the `compat-gap` label. If the difference is a deliberate
   platform subset, cite the row in §6; if it is a retired extension, cite §3.
4. A 2.0 release blocker is an **unclassified** `r=c:no` row: the gate must
   either match GNU or carry a documented reason. "It differs" is not a
   classification.
