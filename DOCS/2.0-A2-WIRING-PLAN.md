## 2. 风险分桶

判定标准（本文件采用，可复核）：

- **A2-安全**：纯读 / 纯计算；不改变权限/属主/属组；无递归删除；不创建设备/FIFO；不创建或删除用户文件（`shuf -o` 这类显式输出文件不算）；不派生进程；不设置系统时钟。stdin 只经既有 v1 整缓冲（`run_command_with_stdin`）即可，不要求新 ABI。
- **A2-需前置**：权限变更（preserve-root 未解禁）、设备/FIFO 平台族、文件创建/清理、子进程派生、系统时钟、流式 follow，或删除旧体即造成 I18N 键/消息面必须同步的那一类。

| 桶 | 数量 | 门表行 | 命令 |
|---|---|---|---|
| **A2-安全** | **18** | **628** | arch groups tty who pinky pathchk factor sum cksum od cut tr head ptx shuf sort df du |
| **A2-需前置** | **13** | **377** | chmod chown chgrp chcon runcon mkfifo mknod date mktemp csplit nice nohup tail |
| 合计 | 31 | 1005 | — |

安全桶内再排序（先小后大，降低单次回滚面）：
**第一波（6 个无 stdin、≤430 Rust 行）**：arch、groups、tty、who、pinky、pathchk；
**第二波（9 个 stdin 过滤器/纯计算）**：factor、sum、cksum、od、cut、tr、head、ptx、shuf；
**第三波（3 个大件，只读但面大）**：sort、df、du。

`sort`/`df`/`du` 仍满足「纯读/纯计算、无权限变更、无递归删除」的安全定义，但 C++ 旧体 1.3k–2.6k 行、Rust 1.1k–3.3k 行，单独成波。

## 3. A2-安全桶接线计划桩

### 3.1 通用约定（对 18 条命令一致）

- **dispatch 位置**：`src/commands/<cmd>.cpp`。`REGISTER_COMMAND(<token>, "<cmd>", …)` 生成 `execute<token><N>(CommandContext<N>&) noexcept`；**只替换这个函数体**，元数据（help/man/completion）逐字节不变。
- **Rust 入口签名**（全部一致，无需改 Rust）：`pub fn <cmd>_cmd(args: &[OsString], io: &mut Io, ctx: &Ctx) -> CmdResult`；`registry()` 已注册（`lib.rs` 行号见各桩）。
- **删除影响面**：31/31 的旧体实现都在 file-local 命名空间（`namespace <cmd>_pipeline` 或匿名命名空间）内（`tty` 没有旧体，只有选项元数据），**没有任何文件 include 它**；CMake 用 `file(GLOB src/commands/*.cpp)`，接线后文件仍保留为注册壳。`tests/unit/<cmd>/` 通过产品 exe 黑盒调用，不引用旧符号，不需要删测试，但 **gate b 失败集必须与基线一致**。
- **读 stdin 的形状**：两种既有写法，不新增 ABI：
  - 名单式：把命令加进 `src/bridge/rust2_bridge.cppm` 的 `kRust2StdinCommands`（当前 `expand/join/numfmt/tsort/unexpand`），handler 直接 `run_command`；
  - 就地判定式（推荐给过滤器）：照 `fold.cpp:58-63` 在 handler 里判 `ctx.positionals.empty() || 任一 == "-"`，走 `run_command_with_stdin`，否则 `run_command`。
  - **已知代价**：v1 是整缓冲 slurp，`head`/`cut` 这类「提前退出」不会像 GNU 一样立刻关上游；这是文档化的价格，不是本 lane 修。
- **I18N**：Rust 侧目前 **0 个 `tr!`/`i18n::text`**（全 31 命令实测）。凡旧体含有 `winux::i18n::...` 键的命令（安全桶：factor/tr/od/who/pinky 共 5 条），接线会**孤立这些 catalog 键**，必须同任务决定「删键 + Rust 加 `tr!` 稳定键 + 英文 fallback」，或在改体前把键迁到 Rust；并同步 `unixwin/winuxcmd-i18n` + `VERSION` bump。其余命令的 Rust 诊断是硬编码英文（`io.stderr` 站点数见各桩），不新增键，但仍受 AGENTS.md「每条用户可见消息需稳定 key + 英文 fallback」的总体门约束。
- **三重门**（照 `REPLACEMENT-RECIPE.md` §3，逐命令相同，只是 `<cmd>`/`<token>` 不同）：
  - **a（GNU oracle）**：`cd rust2 && RUST_BIN=<新 build>/winuxcmd.exe bash gate/run-gate.sh <cmd>`；strict/exit 必须与 WSL coreutils 9.4 逐字节/rc 一致。
  - **b（既有测试）**：全量 `ctest` 失败集 == 接线前基线集；`WINUXCMD_BIN=<dir> bash tests/differential/runner.sh --only <cmd>`（WSL）在新旧 exe 上都过。
  - **c（旧 exe 对拍）**：`CPP_BIN=<接线前基线副本> winuxcmd.exe`（**必须仍叫 `winuxcmd.exe`**，multicall 按 argv[0] 路由）跑同一门表，ledger 每一条 `r=c:no` 都要有解释；stderr/额外 argv 形状另跑 matrix（照 `rust2/gate/wire/truefalse-matrix.sh` + `compare.sh`）。

## 4. echo 裁定（rubash builtin 重叠命令）

### 4.1 现状事实（b781ff35）

| 面 | 事实 |
|---|---|
| 产品接线 | `echo` 已在 `WINUXCMD_RUST2_COMMANDS`；`src/commands/echo.cpp` 只剩 117 行注册壳，handler 为 `return winux::rust2::run_command("echo", ctx.raw_args);`（430ccc3c） |
| 库 | `rust2/crates/winux-cmds/src/echo.rs` 445 行，`echo_cmd`；coreutils 9.4 `echo.c` 语义（手写 `-neE` 扫描、`POSIXLY_CORRECT` 的 `argv[1]=="-n"` 精确规则、sole `--help/--version`、逐字节探针的转义表） |
| 门 | 门表 40 行（38 strict + 2 win，2 条 win 是接线后翻过去的 help/version 行），报告行 40 GREEN，C++ parity 38/40 |
| rubash | `echo` 是 rubash builtin（`src/builtins/echo.rs`，battle-tested `echo.def` 语义）；`command_registry.rs` 把 `/bin/echo`、`/usr/bin/echo` **重定向到 builtin**；shell 用户不会落到 `echo.exe` |
| 发行版 | default edition **保留** echo 的入口链接（`kFullOnlyCommandNames` 只有 `[ false kill test time true` 六个名字），所以 cmd/PowerShell/非 rubash shell 会命中 winuxcmd 的 echo |
| 字节面 | 外部进程 echo 的 argv 来自 Windows UTF-16 → Rust 做一次 lossy 转换；进程内 byte API（`echo_bytes`）**只存在于 wc-xargs2 lane，未在 main** |

### 4.2 裁定

1. **接线本身正确，不产生双语义**。rubash builtin 与产品 echo 是两条互斥路径：shell 内建在进程内执行并劫持 `/bin/echo`、`/usr/bin/echo`；产品 echo 只在外部进程路径被调用。接线没有、也不应该改变 builtin 的行为。
2. **两条路径的字节契约必须分开，不要「统一」**：
   - builtin / xargs 进程内默认 echo（`echo_bytes`）持有**原始字节**，绕过 UTF-8 往返；
   - 产品 echo 只拿到 OS argv（UTF-16），lossy 是 Windows argv 边界的固有代价，不是可以靠 `echo_bytes` 消除的缺陷。
   若未来把 `echo_bytes` 合入 main，它必须是库内 helper（`pub(crate)`），绝不能把产品 handler 改成「读原始字节」以冒充字节精确。
3. **阻塞项（真实缺陷，非猜测）**：main 上 `ECHO_OPTIONS` 仍登记 `-r/--repeat`（`INT_TYPE`）。dispatcher 在 handler 之前做 int 校验，因此 `echo -r x` / 裸 `echo -r` 返回 rc 1，而 GNU 9.4 把它们当数据、rc 0。`GATE-REPORT.md` 的 wave6 wiring 段自己记录了这一点：「GNU rc parity 156/157（唯一 miss 是 `echo -r x`，1.x exe 同样 rc 1）」。修复提交 `234aac52`（Fix #1621，删除 `-r` 注册 + 3 个回归 pin）**不是 b781ff35 的祖先**，未在 main。裁定：echo 的接线验收必须等 #1621 落地；这是元数据一行修复，不涉及 Rust。
4. **`-u/--upper` 仍是「注册但不生效」**：作为 flag 只做 occurrence 记账，Rust 把它当数据打印。help/man 文本还保留 `echo --upper hello`、`echo --repeat 3 hello` 两个示例，属于 help 面与语义面不一致；`-r` 退役也没有 CHANGELOG 条目。裁定：要么在 #1621 的同一批里清掉 help 示例并写 CHANGELOG（推荐的「诚实 help」），要么明确记为「品牌历史面保留」的例外并在 `HELP-SURFACE.md` 登记；不能两者都不做。
5. **验收结论**：echo 可以作为「已接线」计入 main，但**不能**把 wave6 的 echo 行当作 100% 干净；`echo -r` 未过、help 示例未清、CHANGELOG 未记，三项都要在 A2 之前收尾（不阻塞其他命令的接线）。
