## 1. 规范形状：一套加法 API

`CompileOptions`（取自 sed 分支，保持字段/默认值逐字节一致）是**所有非
grep 方言的唯一入口**；`CompileOptions::default()` 与旧的
`Regex::compile_bytes` 完全等价（`Tests::additive_api_shape` 钉住）。

```rust
pub struct CompileOptions {
    pub ignore_case: bool,              // grep -i / sed I / find -iregex
    pub multiline: bool,                // glibc REG_NEWLINE (sed M)
    pub line_delimiter: u8,             // 多行锚点的分隔字节（\n / sed -z 的 NUL）
    pub buffer_anchors: bool,           // GNU \` 与 \'（绝对缓冲区首尾）
    pub posix_strict: bool,             // sed/glibc 严格语法位：CONTEXT_INVALID_DUP/OPS、
                                        //   严格 interval 读取、不接受游离 ERE `)`
    pub strict_utf8_dot: bool,          // `.` 拒绝非 UTF-8 起始字节
    pub no_gnu_ops: bool,               // RE_NO_GNU_OPS（\w \s \b \< \> 等变字面量）
    pub unmatched_right_paren_ord: bool,// RE_UNMATCHED_RIGHT_PAREN_ORD
}
impl CompileOptions {
    pub fn sed(ignore_case: bool, multiline: bool) -> CompileOptions;
}
impl Default for CompileOptions; // 全部 false / b'\n'

impl Regex {
    pub fn compile_with(syntax: Syntax, pattern: &[u8], opts: CompileOptions)
        -> Result<Regex, Error>;
    pub fn new_cache(&self) -> MatchCache;
    pub fn find_at_bytes_with(&self, cache: &mut MatchCache, text: &[u8], start: usize)
        -> Option<Match>;
    pub fn is_match_with(&self, cache: &mut MatchCache, text: &[u8]) -> bool;
    pub fn match_ends_at_bytes(&self, text: &[u8], start: usize) -> Vec<usize>;
}

pub mod dialect {
    pub enum Dialect { FindutilsDefault, Ed, Emacs, GnuAwk, Grep, PosixAwk, Awk,
                       PosixBasic, PosixEgrep, Egrep, PosixExtended,
                       PosixMinimalBasic, Sed }
    pub const DIALECT_NAMES: [(&str, Dialect); 13];
    impl Dialect {
        pub fn from_name(name: &str) -> Option<Dialect>;
        /// 单张映射表：findutils 方言名 -> CompileOptions
        pub fn options(self, ignore_case: bool) -> CompileOptions;
    }
    pub enum DialectError { Regex(Error), BadRepeat }
    pub fn compile(d: Dialect, pattern: &[u8], ignore_case: bool)
        -> Result<Regex, DialectError>;
    pub fn translate(d: Dialect, pattern: &[u8]) -> Result<(Syntax, Vec<u8>), DialectError>;
}

pub mod dfa {
    pub enum LineMode { Contains, Entire }
    pub enum InputRequirement { Any, ValidUtf8, Ascii }
    pub struct LineDfa; // new/from_nodes/find_line/is_match_line/input_requirement
}
```

### 2.1 为什么 `dialect` 仍保留“改写”而不是全塞进 `CompileOptions`

`CompileOptions` 能表达的是 **glibc syntax bits**（哪些 token 是算子、
严格性、锚点、`.` 规则）；emacs 的 `( | { }` 字面量、awk 的
`[]` 内反斜杠转义 / 无 interval / 无反引用，是**词法分类**差异，BRE/ERE
解析器无法用位来表达。因此分两层：

- `Dialect::options(icase)`：一张表，只放可表达的位；
- `translate()`：字节级重写，只做词法分类；
- `compile()`：两行 join。

映射表（`Dialect::options`）：

| 方言族 | `posix_strict` | 其余 |
|---|---|---|
| `posix-basic` `ed` `sed` | true | 默认 |
| `posix-extended` `posix-awk` | true | 默认 |
| `posix-minimal-basic` | false | （`\+ \? \|` 的字面量化在改写层，glibc `POSIX_MINIMAL_BASIC` 不做 CONTEXT_INVALID_DUP） |
| `emacs` `findutils-default` | false | 结构差异全在改写层 |
| `grep` `egrep` `posix-egrep` `awk` `gnu-awk` | false | 同上 |

行为差异（相对 find 分支）：`posix-basic/ed/sed/posix-extended/posix-awk`
现在真正带上 `posix_strict`（严格 interval 读取、`a**` 类 REG_BADRPT、
游离 ERE `)`），比“只靠改写层模拟”更贴近 glibc 的
`RE_SYNTAX_POSIX_*`。find 的 30 行 gate 抽查与 `dialect.rs` 的 7 个内联
GNU 探针测试全部一致（见 §4.3）。

## 3. 健壮性修复（sed 审阅 §3.3）

**问题**：`find_at_bytes_with` 在 NFA 定位出的 bounds 与回溯器锚定复核
不一致时，走 `_ =>` 分支返回 `captures: [whole, unmatched...]`。对
`sed 's/\(a\)/\1/'`、grep `-o` 之类消费方，这不是“慢一点”，而是把
`\1..\9` 静默展开成空串——错误输出。

**修复**（`src/lib.rs`）：

```rust
match self.match_at_bytes(text, begin) {
    Some(m) if m.end == end => Some(m),
    _ => {
        debug_assert!(false, "NFA bounds {begin}..{end} disagree with the backtracker; \
                              falling back to find_at_bytes");
        self.find_at_bytes(text, start)   // 精确的旧路径，绝不再造 span
    }
}
```

- `debug_assert!` 让“不可达”在 debug/测试构建里变成硬失败，而不是悄悄
  降级；
- release 下回落 `find_at_bytes(text, start)`，得到与旧引擎逐字节相同的
  `Match`（含 captures）；
- 文档注释写明该分支是“不可达但必须正确”。

**钉住不可达**：`tests/unify_smoke.rs::nfa_bounds_never_disagree_with_backtracker`
用 12 个模式 × 10 段文本 × 每个 `start ∈ 0..=len`，断言
`find_at_bytes_with` 与 `find_at_bytes` 的 `Match`（begin/end/captures）
完全相等。任一例触发兜底，debug 构建即 panic，测试变红。模式覆盖组的
三种形态：固定宽度（走 `fixed_captures`）、交替/变长重复（走锚定回溯）、
反引用（无 NFA，直接 legacy）。

**有效性自检**（会话内做过，已还原）：把 NFA 返回的 `end` 人为减 1 注入
不一致后，该测试立刻以 `NFA bounds 0..0 disagree with the backtracker`
失败；还原后 68 个测试全绿。说明这条钉子确实咬得住，而非只是文档承诺。

### 4.2 sed：138 组正则对“拍照旧”，新旧 0 差异

`tests/matrix.tsv` 是 GNU grep -o 的 138 组 pattern×input 基线
（65 BRE + 73 ERE）。做法：

1. 把 `origin/main` 的 `winux-regex` 源码抽到 `rust2/target/regex-baseline/`
   作为独立 crate（**不是** git worktree，不污染任何分支）；
2. 同一份 `examples/matrix_harness.rs` 分别跑旧/新引擎，产出快照；
3. 逐行 diff。

```console
$ (baseline) cargo run --quiet --example matrix_harness -- <matrix.tsv> > old.txt
$ (unify)    cargo run --quiet -p winux-regex --example matrix_harness -- \
                 crates/winux-regex/tests/matrix.tsv > new.txt
$ diff <(tr -d '\r' < old.txt) <(tr -d '\r' < new.txt)
# 414 行 / 414 行，0 差异
```

旧快照同时就是 GNU 基线（`tests/matrix_expected.txt`），故本步等价于
“新旧都对 GNU 一致”。

### 4.3 grep：162 行 gate 抽 30 行

`origin/rust2/grep-impl` 的 `gate/cases/{grep,egrep,fgrep}.tsv` 共
142+11+9 = 162 行。抽 30 行（正则相关：BRE/ERE、`-i`、`-w`、`-x`、`-o`、
`-e` 多模式、反引用、POSIX 类、无效正则、CRLF、UTF-8 `.`），把每行自己的
`setup` + argv 原样交给 WSL `grep 3.11 / egrep 3.11`（LC_ALL=C）取期望
stdout，再在 unify API 上重放：

- 编译：`Regex::compile_with(syntax, pat, CompileOptions{ignore_case, ..})`；
- 行选择：`is_match_with`（grep 只问布尔）；
- `-w`：`match_ends_at_bytes` + 词边界判定（GNU `-w` 的“同一起点试更短
  匹配”规则）；
- `-x`：`matches_entire_bytes`；
- `-o`：`find_at_bytes_with` + 多模式取最左、同起点取最长，逐个切片。

结果：**30/30 与 GNU 逐字节一致**（`tests/unify_smoke.rs::grep_gate_rows_smoke`）。
注意 `-P`、`-F`、目录递归等非引擎行未抽取（不动引擎，且属 grep lane 的
命令层验证）。

### 4.4 find：317 行 gate 抽 30 行

`origin/rust2/find-impl` 的 `gate/cases/find.tsv` 共 317 行，其中含
`-regex/-iregex/-regextype` 的 27 行**全部**抽取，另加 3 条同 fixture 的
方言探针（posix-basic interval、sed `\?`、gnu-awk `\w`），合计 30。

做法：同样的 setup+argv 交给 WSL `find (GNU findutils) 4.9.0`，取
`find <start> -print` 作为候选全集、`find <argv>` 作为期望命中集；unify
侧用 `dialect::compile` 编译后用 `matches_entire_bytes` 全串匹配逐个判定。

结果：**30/30 一致**，含 5 个错误行（`-regextype foo` 未知名、`\(a`
未闭合、posix-extended 首算子 `*a`、`sed/posix-basic` 的 `a**`）均按
GNU 的 rc≠0 判为编译错误；`fd152` 的 `-o` 表达式按“两个谓词取并”建模。

### 4.5 没有做的事（诚实声明）

- **不跑三个 lane 的 driver 全量 gate**：本分支没有
  `winux-cmds/src/{sed,grep,find}`（那是 wire 分支的代码），
  `winuxcmd-driver` 里没有这三个命令。命令层 gate 仍归各 lane。
- 因而 grep 只抽 30/162、find 30/317、sed 只跑引擎级 138 对，未跑
  sed 的 381 行 gate。合并后由 wire lane 在自己分支上补齐全量。

## 5. wire lane 如何采纳（rebase 指引）

统一分支的引擎 crate 是**超集**：三条 lane 的引擎增量都已在内，命令层
用法不变。

### 5.1 sed lane（`rust2/sed-impl`）

1. rebase 后**删除**本 lane 对 `rust2/crates/winux-regex/**` 的全部改动
   （`lib.rs`、`parser.rs`、`ast.rs`、`matcher.rs`、`fastpath.rs`、
   `pike.rs`、`tests/{pike_equiv,sed_dialect}.rs`），以 unify 版为准；
2. `sed/compile.rs` 的 `CompileOptions::sed(icase, mline)` 与
   `cache: winux_regex::MatchCache` 无需修改；
3. 唯一行为差异：§3 的兜底修复（只影响不可达分支）。

### 5.2 grep lane（`rust2/grep-impl`）

1. 删除本 lane 的 `src/dfa.rs`、`tests/{dfa_equiv,match_ends}.rs`、
   `lib.rs` 的 `pub mod dfa;`、`matcher.rs` 的 `match_ends_at_bytes`；
2. `grep/pattern.rs` 对 `LineDfa`/`match_ends_at_bytes` 的调用不变；
3. 注意：unify 版 `dfa` 对 sed 方言节点返回 `None`（走解释器）。grep
   永远不编译这些节点，行为不变。

### 5.3 find lane（`rust2/find-impl`）

1. 删除 `src/dialect.rs` 与 `lib.rs` 的 `pub mod dialect;`；
2. `dialect::compile(d, pat, icase)` 签名不变；
3. 若 `find/rx.rs` 需要新的方言位，改 `Dialect::options` 这一张表，
   不要另起编译入口；
4. 语义变化：strict 族现在真正带 `posix_strict`（§2.1），30 行 GNU
   gate 抽查无差异。

### 5.4 合入顺序

任一 wire 分支先合入时把 unify crate 整体带进主干；其余两条 rebase 到
新主干后**只删自己的引擎副本**，然后跑：

```console
cargo test -p winux-regex          # 应为 68 passed
cargo test -p winux-regex --no-default-features
```

若对方已合入更快的版本，以对方为准，本分支的 API 映射（§2）作为核对表。

## 7. 复现抽查数据（附录）

期望字节来自 GNU oracle，不是引擎自证。重放脚本（会话内，不提交）
做三件事，与 `gate/run-gate.sh` 的 GNU 侧同构：

1. 解析 TSV：`id | mode | setup | env | stdin | argv...`；
2. 在临时目录执行该行的 `setup`（`printf ... > f` 等），再原样执行
   `grep/egrep/find <argv>`（stdin 列按 `printf %b` 解释）；
3. 记录 `stdout`、`rc`；find 额外跑一次 `find <start> -print` 作为候选
   全集。表数据即该 dump 的逐字节转写。

```console
$ wsl bash -lc 'grep --version | head -1; find --version | head -1'
grep (GNU grep) 3.11
find (GNU findutils) 4.9.0
```

抽样行数：grep 30 / 162，find 30 / 317（其中 27 行是全部正则行），
sed 138 / 138（基线全量），兜底钉 12 模式 × 10 文本 × 全部起点。
