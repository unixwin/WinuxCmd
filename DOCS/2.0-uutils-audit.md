# WinuxCmd 2.0 rust2 vs uutils/coreutils 对照审计（#1488）

> 只读对照审计：不改任何命令实现代码。审计决定架构路线（自研保留 / 按
> uutils 改算法 / 整体采用 uu_* crate），所有数字可复现，方法见 §1。
>
> - 我们的侧：`rust2/` @ main `041c98ff`（wave1-3a + wiring）∪ wave3b
>   `ea53c38a`（8 个新命令）= **47 个已实现命令名**（含 `[`、`sync`；票面
>   写 44 是近似值）。std-only 零依赖，全部 `fn run(args, io, ctx) ->
>   CmdResult` 显式 IO 形态。
> - uutils 侧：github.com/uutils/coreutils @ `156d715`（main，2026-11，
>   109 个 uu crate）。
> - GNU oracle：WSL coreutils 9.4（与 gate 相同）。
> - 实证产物（不入库）：`target/uutils-audit/samples/`（seq/numfmt/b2sum
>   三方脚本与输出）。

## 1. 方法

1. **逐命令源码对照**（§3 表）：我们的实现头注释逐条声明移植自哪个 GNU C
   函数（seq.c print_numbers/fast_inc、fmt.c fmt_paragraph 成本 DP、
   digest.c digest_check/split_3 等），uutils 侧读对应 `src/uu/<c>/` 的算
   法选择、`Cargo.toml` 依赖、`cfg(windows)`/`cfg(unix)` 分支密度。
2. **Windows 支持以 uutils 的 feature 树为准**（`Cargo.toml`
   `feat_os_windows = feat_Tier1 + stdbuf`；`feat_require_unix_core` 与
   `feat_require_unix_utmpx` 是官方"仅 unix 可用"清单），不是猜测。
3. **依赖足迹用 `cargo tree --edges normal`** 在 uutils 树上实测（§5）。
4. **抽样实证（§4）**：seq、numfmt、b2sum 三个命令编译出 uutils 原生
   Windows 二进制（`cargo build --release -p uu_seq -p uu_numfmt
   -p uu_b2sum`，MSVC 成功），与我们 driver、WSL GNU 9.4 三方逐 case
   比对 stdout 字节 + 退出码（stderr 只记录不 gate，同 gate 规则）。
5. **库形态就绪度（§6）**：读 uumain 签名与 uucore 宏/exit 路径 + 上游
   discussion #6103 / issue #5088。
6. **许可（§7）**：对 10 个样本 crate 的 180 个传递依赖逐个扫 license 字段。

## 2. 结论先行

**推荐路线：A（自研保留）+ "借算法"支线；B/C 均否决。**

- **47/47 命令建议 keep 自研，0 命令建议 adopt uu_\*。** 否决的直接原因
  不是质量，而是三个硬条件不满足：
  1. **显式 IO 契约（#1488 硬契约）**：uu_* 全系 `uumain(args) ->
     UResult<()>`，内部 `stdout().lock()` / uucore `show_error!` 直接写
     进程 stdio，`uucore::bin!` 以 `process::exit` 收尾——不可注入。进程内
     调用只能靠 FD 重定向 shim，正是 niubash#727 定性为 204 格 56 格损坏
     根因的进程级 CRT stdio 形态。上游自己也把"结构化返回/可嵌入"列为未
     完成的开放设计（discussion #6103、issue #5088）。
  2. **Windows 缺口打在我方 parity 正面上**：uutils 官方将
     `chmod chown chroot groups id install logname mkfifo mknod stat stty`
     列入 `feat_require_unix_core`（仅 unix 可用），`pinky users who` 列入
     utmpx 系（仅 unix），`getconf` 上游根本不存在。**47 个命令里 uutils
     在 Windows 上缺 6 个，恰好都是我们 C++ value-model parity（gate 的
     `win` 类）最吃重的命令**（chmod/chown/id/stat/users/getconf）。
  3. **依赖足迹**：uu crate 单只起步 53 个传递 crate（clap+fluent+uucore
     基线），b2sum 系 128、seq 93、numfmt 92、test 97；40 只可构建
     crate 并集 **220 个传递 crate**，与我们 std-only（0 依赖）政策冲突。
- **借算法支线（2 条，本次实证抓到 1 个真 bug）**：
  - `numfmt --field`：GNU/uutils 把转换字段按原字段宽度补齐、行内其余
     内容原样保留（多空格不塌缩）；我们 wave3b numfmt 塌缩为单空格。
     gate 74 case 全绿但没测到"原字段宽于输出"形状。**修法**：借
     numfmt.c 的行重组语义（字段原样复制 + 按原宽补齐），不需要引依赖。
  - `seq` 浮点路径：GNU 用 80-bit long double；我们用 f64（已文档化的
     >16 位有效数字分歧）；uutils 用任意精度十进制（ExtendedBigDecimal）。
     实证 case5（`seq 0.9999999999999999999 1.0000000000000000002`）
     uutils/GNU 一致、我们偏差。**修法**：借"精确十进制"思路，用我们
     seq 整数路径同款 string/decimal 技术实现小数精确累加，0 依赖。
- **uutils 的第二个价值是"第二 oracle"**：它与 GNU 9.4 在抽样上高度一致
  （见 §4），可入库做我们 gate 的交叉校验源（Windows 原生跑，零成本），
  特别适合给 `win` 类 case（无 GNU 对比面）增加一个独立参照。

## 4. 抽样实证（三方实测，非读码）

脚本与原始输出：`target/uutils-audit/samples/`（`three_way_*.sh`、
`g*.out/r*.out/u*.out`）。规则同 gate：stdout 字节 + rc 必须相等；
stderr 只记录（GNU 用 Unicode 引号，措辞不 gate）。

### 4.1 seq（uutils 93 依赖 vs 我们 0；双快路径）

| case | GNU 9.4 | rust2 (driver) | uutils seq.exe |
|---|---|---|---|
| `seq 100000000000000000000 100000000000000000005`（21 位整数） | 6 行步进 1 | **一致**（string-increment 快路径） | **一致**（EBD 精确十进制） |
| `seq 0 0.1 0.5` / `-w 8 12` / `-w 00 10` / `0 0.000001 0.000003` | — | 一致 ×4 | 一致 ×4 |
| `seq 0.9999999999999999999 1.0000000000000000002` | `0.9999999999999999999`（long double 就地舍入终止） | **偏差**：打 `1.0000000000000000000`（f64） | **一致**（EBD 精确） |

结论：我们 6/7、uutils 7/7。uutils 用任意精度十进制消掉了我们唯一的已
文档化分歧类。**采纳其算法思路**（小数精确累加）即可，不必引 bigdecimal
栈——我们整数路径已有 string-increment，同技术可扩到定点小数。

### 4.2 numfmt（uutils 92 依赖 vs 我们 0）

14 case：uutils 14/14 与 GNU 一致；我们 13/14（13 个三方全等，含
`--to=si 12345678901234567890` → `13E` 大整数精度、`--padding=10`、
`--suffix=B`、`--from=iec-i`、`--invalid=warn` 穿透 + rc、非法
`--round=ceil` 三方同样报错退出）；1 个我们偏差：

- 输入 `plain 1048576 line`，`numfmt --field 2 --to=iec`：
  GNU = `plain    1.0M line`，uutils = 同 GNU；**我们 = `plain 1.0M
  line`**（转换字段未按原字段宽补齐，行重组塌缩了空格）。gate 74 case
  未覆盖"原字段宽 > 输出宽"形状 → 是审计新发现的真 gap。
- **行动项**（不在本审计改码）：按 numfmt.c 的行复制语义修 wave3b
  numfmt 的 field 路径，并给 gate 补该形状 case。

### 4.3 b2sum（uutils 128 依赖 vs 我们 0；自研 BLAKE2b）

13 case 三方**全等**（stdout 字节 + rc）：默认输出、空文件、1 MiB 随机
文件、`-l 8/256/512` 截断、`--tag`、`-z`（NUL）、stdin `-`、多文件、
`-c` 通过 / `-c` 篡改(rc1) / `-c --quiet` 篡改(rc1)。我们的自研
BLAKE2b（RFC 7693）与 digest_check/split_3 移植在与 GNU 9.4 的字节级
比对上无任何暴露面；票面"b2sum --check 推迟"与代码不符（已实现）。

## 5. 依赖足迹量化（选项 B/C 的成本面）

`cargo tree --edges normal`，Windows/MSVC host，uutils @ 156d715：

| 项 | 数值 |
|---|---|
| 基线（任何 uu crate，即 clap + fluent + uucore 闭包） | **53 crates** |
| 轻量命令（true/false/dirname/unlink/printenv/pwd/basename…） | 53 |
| 中量（chmod 不可构建除外；truncate/tee/df/sleep…） | 58–64 |
| 显式增量大户：b2sum 系 128（blake2b_simd/md-5/sha1/sha2/digest/memmap2）、seq 93（bigdecimal+num-bigint+num-traits）、numfmt 92、test 97、join 95、paste/fold 82、mkdir 89、printenv 88 | — |
| 40 只可构建 crate 并集（选项 B/C 全量） | **220 crates**（不含 chmod/id/stat/users——它们在 Windows 无法构建） |
| 对比：rust2 现状 | **0 依赖**（std-only） |

fluent（i18n 运行时）是每只 crate 的硬依赖：错误措辞走翻译资源，即使只
用英文也拖着 fluent/fluent-syntax 闭包。这与我们"GNU 措辞、stderr 不
gate"的零依赖路线是两种维护模型。

## 6. 库形态就绪度（#1488 显式 IO 契约）

- 形态：`pub fn uumain(args: impl uucore::Args) -> UResult<()>`；argv 可
  注入，**stdio/env/cwd 不可注入**（例：uu_seq 内部 `stdout().lock()`，
  numfmt 6 处进程 stdio 引用；uucore `show_error!` 系宏直写进程 stderr；
  `uucore::bin!` 宏以 `process::exit` 结束进程）。
- 上游状态：无可嵌入/结构化返回的官方 API；维护者指向"直接调 uumain 或
  用 uucore 内部函数"（discussion #6103），nushell 深度集成的诉求
  （issue #5088）仍以 uumain 形态讨论中。**没有 library-ization 路线图
  承诺。**
- 若强行采用：要么 fork 全系把 Io 参数穿进去（每次 upstream rebase 都是
  全量冲突面，220 依赖闭包还要同步升级），要么在宿主做 FD 级重定向
  shim——后者正是 niubash#727 定性为 204 格 56 格损坏根因的进程级 CRT
  stdio 形态，直接违反 #1488 的存在前提。
- 对比：rust2 的 `Io { stdin: &mut dyn Read, stdout/stderr: &mut dyn
  Write }` + `Ctx { cwd, env }` + `catch_unwind` 边界（ABI_FAILURE 125）
  + `winuxcmd_run` 显式缓冲区 ABI 已是该契约的成产品实现，47 命令全部
  就位。

## 7. Windows 支持与许可

- uutils Windows 官方特性集 = `feat_os_windows`（feat_Tier1 + stdbuf）；
  Tier1 = feat_common_core + df/du/env/hostname/kill/nohup/nproc/more/
  sync/timeout/uptime/whoami。`feat_require_unix_core`（chmod、chown、
  id、stat、…）与 `feat_require_unix_utmpx`（users、…）明确排除在
  Windows 外。df 的 Windows 路径（fsext/windows.rs，FindFirstVolumeW/
  GetDiskFreeSpaceExW/GetVolumeInformationW）与我们同 API 面、同"无
  inode"限制。我们的 value-model 命令（uname/id/hostname/hostid/users/
  stat/chmod/chown/getconf）在 uutils 上**没有 Windows 对应物可对照**，
  C++ parity 只能自研维持。
- 许可：uutils 本体 MIT。10 样本 crate 的 180 个传递依赖逐一扫 license：
  167 个 permissive（MIT/Apache/BSD/ISC/Unicode/Zlib…），唯一双许可边是
  `self_cell (Apache-2.0 OR GPL-2.0-only)`（取 Apache 分支即无 copyleft），
  其余 13 个为 workspace 内无 license 字段的 uu crate（随本体 MIT）。
  **无 copyleft 传递**——许可不是否决项，§2 的三条才是。

## 8. 三个选项的最终量化

| | A 全自研保留（现状+2 借算法） | B 按命令采用 uu_* | C 整体搬迁 uutils |
|---|---|---|---|
| 依赖增量 | 0 | 基线 53/crate；全量 220 crates | ≥220 crates（含 fluent 全栈） |
| #1488 显式 IO 契约 | 已满足 | **每只 crate 都要 fork 改 IO** | 同左，全量 fork + 宿主 FD shim（违反 niubash#727 教训） |
| Windows 覆盖 | 47/47（含 value model parity） | 可选面 41/47；**chmod/chown/id/stat/users/getconf 无货** | 同左 6 命令必须自研补齐 = 回到 A 的那一半 |
| 需重过的 gate 面 | 2 个算法修（seq 浮点、numfmt --field）+ 补 case | 被采纳命令全部 strict/exit 重跑 + note 类重判 | 全部 1288 case 重跑（wave1 402 + wave2 348 + wave3a 240 + wave3b 276 + sync 22），C++ parity 列全废 |
| C++ parity（1.x 承接） | 保持 | 交互面混合两种措辞/退出模型 | 废弃重做（uutils 措辞≠1.x，且 6 命令无货） |
| 上游同步成本 | 0 | 每命令升级时 IO-fork 冲突 | rebase 全量冲突 + 220 依赖升级审计 |

## 9. 审计过程附带发现（记录，均不在本审计改码）

1. `numfmt --field` 塌缩空格（§4.2）——唯一真语义 gap，建议进 gate。
2. main 分支 registry 漂移：`uname id hostname getconf` 模块已实现且有
   gate 表，但 `winux_cmds::registry()` 未注册（driver 报 unknown
   command）；wave3b 分支已注册它们但缺 `sync`（main 有）。两分支合并时
   以"47 名全注册"为准。
3. 票面信息修正：`b2sum --check` 已实现且三方实证全绿，"推迟"过时。
4. uutils 可作第二 oracle：其 Windows 原生二进制与 GNU 9.4 抽样高度一
   致（seq+numfmt+b2sum 合计 34/34 case；我们同批 32/34），对 gate 的
   `win` 类（无 GNU 对比面）是免费的独立参照。建议以工具（不入代码库）
   形式保留在 CI 旁路。
