# Recursive grep: reuse directory metadata

The Rust recursive walker discarded `DirEntry` after copying its name and
path, then called `symlink_metadata` on every child. On Windows the directory
entry already contains non-following metadata, so that repeated path query
opens the file again solely to classify it.

Keep each entry until it is visited and call `DirEntry::metadata`. Regular
files still use the existing open and streaming scanner. `-r` still skips
links encountered during traversal; `-R` still follows their target metadata
and checks directory cycles. Explicit operands, exclusions, diagnostics,
output ordering, and early-stop behavior keep their existing paths.

GNU grep 3.11 `src/grep.c:597` enables `FTS_NOSTAT`;
`src/grep.c:1656 grepdirent` consumes the known entry type and only queries
status when that type is unknown. This change follows that distinction. Rust
documents `DirEntry::metadata` as non-following and free of additional system
calls on Windows; on Unix it performs `symlink_metadata`:
<https://doc.rust-lang.org/std/fs/struct.DirEntry.html#method.metadata>.

## Paired result

Windows 11 10.0.26300, Ryzen 7 6800HS, MSVC 14.44.35207, Rust 1.99.0,
Release, Rust2 enabled. Base commit:
`cb8962426537be6316c781590953d84fdb8f1776`.

Both arms run `winuxcmd.exe grep -rl needle data` over one fresh directory
containing 2,000 matching files. Every invocation checks the complete filename
list and empty stderr. Two warmup pairs precede 30 alternating measured pairs;
no local build or test ran concurrently. Timings include process startup and
output collection; they are not full shell or host acceptance measurements.

| Arm | p50 (ms) | p95 (ms) |
| --- | ---: | ---: |
| Unchanged base | 574.791 | 640.322 |
| Reuse directory metadata | 360.266 | 428.095 |

This removes 37.3% of the median in this fixture. The downstream 60 ms target
is still unmet. Raw samples and binary hashes are in
[`tests/benchmark/grep-directory-metadata.json`](../tests/benchmark/grep-directory-metadata.json).

Reproduce, keeping both executable basenames `winuxcmd.exe`:

```powershell
python scripts/benchmark-grep-walk.py baseline/winuxcmd.exe build-vs/winuxcmd.exe result.json
```

## Validation and limits

- 21 focused grep tests passed, including a new Windows junction fixture for
  recursive skip, dereference, explicit operands, exclusions, and dangling
  target errors.
- All 976 Rust command tests passed.
- Existing grep/egrep/fgrep differential gate: all 162 rows match the
  unchanged executable's status and stdout. GNU-gated rows: 153 passed,
  2 failed; 7 Windows-only rows passed; no skipped rows.
- The installed oracle is GNU grep 3.12 on Ubuntu 26.04.1, rather than the
  library's 3.11 reference. `gp92-u-warning` differs because 3.12 rejects the
  retired `-u` option. `gp141-exc-inc-order` prints the same two matches in
  the opposite filesystem enumeration order. Both differences also occur
  with the unchanged executable. The GNU gate is not described as green.
- I18N review: no runtime message, key, help, option, or version changes.
  The added test asserts existing output. No catalog update is required.

## 中文说明

递归扫描原先丢弃目录枚举返回的元数据，再对每个文件调用
`symlink_metadata`。Windows 的 `DirEntry::metadata` 已持有不跟随链接的
元数据，因此可以省去这次重复查询；Unix 仍走原有的非跟随查询语义。
文件打开、流式匹配、`-r`/`-R` 链接策略、排除规则、错误报告和输出顺序
保持原有路径。

同一台机器、同一个 2,000 文件样本集，30 组交替测试的中位数由
574.791 ms 降至 360.266 ms，p95 由 640.322 ms 降至 428.095 ms。
每次调用均校验完整文件名集合。此结果包含进程启动及输出收集，尚未达到
下游 60 ms 目标，也不代表宿主或完整场景验收完成。

21 项 grep 测试和全部 976 项 Rust 测试通过。差分测试的 162 行与未修改
程序完全一致；当前 GNU 3.12 参照下仍有两项既有差异（移除的 `-u` 选项、
文件系统枚举顺序），因此不将 GNU 差分门禁标为全绿。
