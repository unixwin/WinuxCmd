## 0. 结论摘要

### 0.1 先纠正 inventory：它不是一个 59 / 23 / 94 的真实快照

`DOCS/2.0-inventory.tsv` 当前写的是 **wired 59 / rust-ready 23 / c++-only 94**；main 的权威接线面（`CMakeLists.txt` 的 `WINUXCMD_RUST2_COMMANDS`）已经是 **68 个 applet**。差额 9 条全部是可复核的接线 commit：

- 4 条仍标 `c++-only` 但已 wired：`find`、`grep`、`mv`、`sed`；
- 5 条仍标 `rust-ready` 但已 wired：`arch`、`groups`、`nohup`、`pinky`、`who`。

因此真实分布是 **wired 68 / rust-ready 21 / c++-only 87**（68 + 21 + 87 = 176）。其中 rust-ready 21 = inventory 的 23 − 已 wired 的 5 + 从 c++-only 迁入的 `cp` / `ls` / `rm`。

> **口径修正（重要）**：`CMakeLists.txt` 的列表是 **68 项**，不是 69。用 `sed -n '/set(WINUXCMD_RUST2_COMMANDS/,/)/p'` 取范围时会把下一行的注释 `# Command-set edition shipped ... (#1438)` 也带进来（`sed` 的范围结束行从“匹配行的下一行”开始找），多算 1 行。用 Python 的 `set\(WINUXCMD_RUST2_COMMANDS\s+"([^"]*)"\)` 精确取，得到 68 个名字；`test_bracket` 物化为 `[`，与 inventory 的 `[` 是同一 applet。

### 0.2 四类统计（对 94 条 inventory 行）

| 分类 | 条数 | 说明 |
|---|---:|---|
| **A. 该做** | **73** | 71 条需要新 Rust 实现 + 2 条只差接线（`ls`、`rm`） |
| **B. deferred 有据** | **1** | `cp`：有明确回退理由（6 个 symlink 复现单元红） |
| **C. retired** | **0** | 当前没有命令级退役；`link` 不在 176 applet 内 |
| **D. 保留面** | **16** | 平台专属/自有桥接面，有 `MIGRATION.md` / `edition-audit.md` / regex decision doc 锚点 |
| **已完成（inventory 过时）** | **4** | `find`、`grep`、`mv`、`sed` 已 wired |
| **合计** | **94** | 73 + 1 + 0 + 16 + 4 = 94 |

**判据 1 的真实剩余工作量 = 74 条**：A 73（其中 71 条要写实现、2 条只差接线）+ B 1（`cp` 重接）。再把 16 条 D 按判据 2 记成保留面后，`c++-only` 才能字面归零；但 inventory 目前没有 `retained(...)` 状态，见 §7.1。

### 0.3 三条会改变施工顺序的实测结论

1. **`ls` 的 8 个阻塞 issue 全部已关闭**：`#1639`–`#1646` 均为 `CLOSED`（修复 PR `#1694`、`#1733`）。`ls.rs` 已在 main（5288 行，gate 148 行），`registry()` 已注册，`CMakeLists.txt` 未列——**只差接线，没有未清 compat-gap**。
2. **`rm` 的阻塞 issue 也全部已关闭**：`#1650`、`#1672` 均为 `CLOSED`（修复 PR `#1700`）。`rm.rs` 已在 main（1725 行），**只差接线**。
3. **`cp` 的 `#1757` 已被回退 PR 关闭，不是“等修”状态**：`#1795`（`55d85ba8`）把 `cp` 从 `WINUXCMD_RUST2_COMMANDS` 移除并恢复 C++ 路径，同时 `Closes #1757`；Rust 库仍在 main 等待 reland。要保持 `deferred(issue)`，必须**重开 #1757 或新开一个 cp re-land issue**——当前 0 个 open issue 跟踪它。

另外：`#1488`（2.0 命令库化 epic）本身已是 `CLOSED`。94 条里有 **86 条**的唯一 anchor 是 `#1488 (waveN)`，而 `#1488` 不是 open issue；它只是排期，不能当作 `deferred(issue)` 的合法依据。这正是 71 条 A 类“该做”的判定基础。

## 1. 判定规则（本文实际使用的口径）

| 类别 | 判定规则 | 采用的锚点 |
|---|---|---|
| **A. 该做** | anchor 只有 `#1488 (waveN)` 排期；没有“不做/保留/退役/回退”的反证；命令用户可见、属于 GNU/util-linux/procps/findutils 等命令面 | inventory `anchor` 列；`#1488` 的 CLOSED 状态；源码有真实实现（不是无条件占位） |
| **B. deferred 有据** | anchor/issue/PR 明确写了暂不做或回退的**原因**；保持 `deferred(issue 号)`，不臆造进度 | `#1757` / `#1795` / `55d85ba8` / 6 个失败测试名 |
| **C. retired** | 命令级退役（从命令面移除）或被其他命令取代；选项级退役不算 | `MIGRATION.md` §3（只列选项级）；`inventory-summary.md`（`retired = 0`）；`AGENTS.md` Banned commands |
| **D. 保留面** | 平台专属能力、Windows 自有工具/桥接面，或非 GNU 命令；decision/audit 文档明确“保留/不裁/full-only” | `MIGRATION.md` §2/§7；`edition-audit.md` §4.2/§4.3；regex decision doc §6/§8 |
| **已完成** | 命令名在 `WINUXCMD_RUST2_COMMANDS`，且 `src/commands/<cmd>.cpp` 调 `winux::rust2::run_command_with_stdin_streaming` | `CMakeLists.txt` + 接线 commit |

**关于 `#1488`**：它是“2.0 命令库化”的总 epic，`wave2/3/4` 只是排期。本文不把 `#1488 (waveN)` 当作 B 类依据——否则 94 条几乎全会被错误地“deferred 合理化”。更何况 `#1488` 已经 `CLOSED`。

**关于 `link`**：`AGENTS.md`「Banned commands」明确永不添加 `link`（MSVC `link.exe` 冲突，`WINUXCMD_BANNED_COMMANDS`）。它**不是** 176 applet 之一，`DOCS/2.0-inventory.tsv` 没有 `link` 行；所以 C 类为 0，而不是漏判。

**关于 `grep -P`**：`grep` 的非 `-P` 面已 wired；`-P`/PCRE2 是**面级**保留（`DOCS/2.0-regex-engine-decision.md` §6 推荐 4、§8 裁定点 2），不是整条 `grep` 的保留。`grep` 行因此记“已完成”，D 只记 `-P` 面。

## 7. 风险与待裁定项（不阻塞本分类）

1. **inventory 的状态词表缺 `retained(...)`**：判据 1 只允许 `rust2-wired` / `retired(...)` / `deferred(issue)`，但 D 类 16 条是判据 2 允许的保留面。建议给 inventory 增加第 4 个状态 `retained(<decision-doc-anchor>)`；否则“零 `c++-only`”无法字面成立。若不新增状态，则 D 类必须补 `deferred(issue)`（每条一个 issue），但这会把“保留”误记成“欠账”。
2. **`#1488` 已 CLOSED**：86 条的唯一 anchor 是 `#1488 (waveN)`，其中 71 条 A、15 条 D。`deferred(#1488)` 不是合法的 open-issue 锚点。建议二选一：重开一个 2.0 清零 epic 并按 wave 拆 sub-issue；或直接按本表的 A 批次开工，不再依赖 epic 记账。
3. **`cp` 的 B 类是“临时回退”而非“永远不做”**：`#1757` 已被 `#1795` 关闭，当前没有 open issue 跟踪 reland。要保持 B 的合法性，需重开 #1757 或新开 `cp re-land` issue；否则 cp 应回到 A-wire（但接线前仍会被 6 个 symlink 单元挡住）。
4. **`ls`/`rm` 已无阻塞 issue**：本表把它们记 A-wire；如果 owner 认为“库在 main 但没接线”也应算 deferred，则它们会落到 B，A 降到 71、B 升到 3。本文按“只差接线 = 该做”处理，因为它们没有任何未清的兼容缺口。
5. **`tic` 的 D 证据偏弱**：源码明确“Windows 无 terminfo 编译器”，但没有一份 decision doc 说“保留 C++、不移植”。如果按“D 必须有正式锚点”严格执行，`tic` 应移到 A（66 行，`-V` + 错误消息，工作量极小）。`chroot` 同理（96 行），只是 edition audit 明确点名了它。
6. **`mkgroup`/`mkpasswd` 是“建议 full-only（待裁）”**：本文按 edition audit 的显式建议归 D；若 captain 决定移出默认面但保留 verb，分类不变（仍是保留面），只是 edition 名单变化。
7. **`grep -P` 的 D 是面级**：整条 `grep` 已 wired；不要把 `grep` 行误标回 `c++-only`。
8. **`w` 的 `test_coverage=none`、`whereis` 的 `differential:3` 无 unit 是测试缺口**，不是 defer 理由；移植前应先补差分/oracle。
9. **`locale`/`stdbuf` 的 `oracle_status=unreviewed`**：移植前先补 oracle，不是保留面。
