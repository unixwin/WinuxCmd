# WinuxCmd 2.0 wave1 — differential gate report (#1488 pilot)

Oracle sides: **Rust** driver (`rust2/target/debug/winuxcmd-driver.exe`),
**GNU** coreutils 9.4 under WSL (`env <name>`, native ext4 scratch),
**C++** 1.x dispatcher (`build-vs/usr/bin/winuxcmd.exe`, Debug).

Gate rules per case (`gate/cases/<cmd>.tsv`, generated by `gate/gen-cases.py`):

- `strict` — stdout bytes AND exit status must equal GNU (byte-for-byte).
- `exit` — exit status must equal GNU; stdout is platform-form-bound
  (POSIX vs Windows path shapes) and is recorded, not gated.
- `win` — no GNU comparison possible (platform-inherent output);
  Rust vs C++ exit status gated, stdout recorded.
- `note` — record-only: cases where the 1.x C++ applet itself deviates
  from GNU; the Rust pilot follows GNU and the C++ divergence is
  inherited-not-fixed, so the case never gates.
- stderr wording is NEVER gated (GNU uses Unicode quotes); first
  divergences are recorded under `target/gate/gnu-stderr-samples.txt`.

## Wave3a (#1488, third batch)

8 commands: `seq fold paste tee fmt stat touch ln` (240 cases). All five text
commands gate strictly against GNU coreutils 9.4 byte-for-byte (seq's
arbitrary-precision integer fast path + f64 long-double path, fold.c's
byte/column algorithm, paste.c's parallel/serial delbuf algorithm, tee.c's
EPIPE-silent failure model, fmt.c's full cost DP). stat renders GNU's exact
default/terse/-c format shapes over the Windows value model of the 1.x
applets (uid 0x30000+RID, POSIX-shaped mode words, volume-serial device),
so its value cases gate Rust-vs-C++ rc (win) while rc-only and platform-neutral
stdout cases stay strict against GNU. touch sets times through SetFileTime with
a DST-aware TzSpecificLocalTime conversion (no CRT timezone touch) and a probed
GNU parse-datetime subset (-d ISO/@epoch/time-only/-t [[CC]YY]MMDDhhmm[.ss]).
ln uses CreateHardLinkW and CreateSymbolicLinkW (unprivileged flag; the 1.x
C++ lacks it, so symlink-creation cases are `note`: GNU rc 0, Rust rc 0,
C++ rc 1). Known GNU-vs-C++ divergences the Rust side follows GNU on:
`stat -c %C` rc (GNU 0, C++ 1), `ln -i` decline rc (GNU 1, C++ 0 observed as
no-op), tee fold trailing-space (fold C++ drops it). Documented subset: touch
relative dates ("next monday") are rejected like GNU rejects unparseable
dates; seq f64 vs 80-bit long double only differs >16 significant digits;
fmt buffers whole paragraphs (GNU flushes at 5000 chars / 1000 words).

**Refresh (#1488 wiring wave, true/false):** the pilot's `true`/`false`
honored `--help`/`--version` in any position and returned 0 for `false
--help`/`--version`; GNU (true.c, `argc == 2`, EXIT_STATUS kept) honors them
only as the sole argument and `false` keeps status 1. truefalse.rs now follows
the sole-argument rule, so t06/t14/f06/f14 were promoted to `strict` and f07
became `win` (branded version text, like t07). Rows re-measured with
`bash gate/run-gate.sh true false`: 38 GNU-gated + 2 win, all green. The
three former `note` rows were the pilot diverging, not the C++ applet.

**Refresh (#1488 rust2 wave1 deepening, chmod/chown/df):** the pilot's
platform-subset commands were pushed to "everything Windows can honestly
do", GNU semantics per coreutils 9.4 probed under WSL:

- `chmod` — full GNU modechange grammar in `modemap.rs`: multi-op clauses
  (`u+r-w`), omitted-who umask exclusion (`=w` on 044/umask 022 -> 0200),
  `X` on dirs/pre-executable files only, copy forms (`u=g`, `u+g`),
  special bits (`s`->u/g, `t`->o, misplaced silently no-op like GNU
  `g+t`), `=` replacing the affected who's special bits, octal values
  fitting 0o7777 (`00000644` ok, `077777` invalid). `-R` keeps GNU fts
  preorder, skips symlinks, refuses filesystem roots (upstream default
  preserve-root; the WSL oracle build has it disabled — never aim `-R`
  at `/` in the gate). `-v`/`-c` follow GNU wording
  (`mode of 'f' changed from 0644 (rw-r--r--) to 0755 (rwxr-xr-x)`),
  `-f` suppresses diagnostics. NTFS persistence stays the documented
  subset: read-only attribute tracks owner-write; x/s/t bits live in the
  in-memory model only. Cases 22 -> 45 (strict 21 -> 41).
- `chown` — real ownership changes via advapi32 SetNamedSecurityInfoW:
  owner-to-self and owner+group apply where the OS grants WRITE_OWNER;
  the unprivileged desktop denial maps to GNU's `changing ownership of
  'f': Operation not permitted` rc 1 (probed: even same-group
  GROUP_SECURITY_INFORMATION is rc 5 ERROR_ACCESS_DENIED without
  SeRestorePrivilege). Numeric uid/gid stay validated no-ops (no Windows
  model); `owner:` trailing colon follows GNU (`root:` ok, `1234:`
  invalid spec), `--from` filters by SID, `--reference` copies both
  SIDs, `-v`/`-c` follow GNU describe_change wording. Cases 16 -> 37
  (strict 12 -> 22; 4 notes: OS-denied group set, cpp pilot diverges).
- `df` — GNU 12-column `--output` model (source,fstype,itotal,iused,
  iavail,ipcent,size,used,avail,pcent,file) with GNU's field-error
  wordings, `-t`/`-x` exact fstype filters, `--total` summary row,
  `-i`, `-B`/`--block-size` with SI/binary suffixes and ceil division,
  dynamic column widths, `df <path>` mount-point resolution with
  same-fs dedup, fstype from GetVolumeInformationW, bounded probe for
  remote drives. Inode columns report 0 with `IUse%` `-` (no NTFS
  inode counts — documented deviation); source column is the drive
  letter / UNC share (value model). Cases 15 -> 35.
