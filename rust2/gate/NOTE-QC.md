# Gate note-class QC — NOTE-QC.md

Notes are record-only rows (`mode = note`) and never gate. This
report is their standing audit: what each note claims, what GNU
actually does today, and whether the note still earns its
immunity. Generated by `python gate/qc_note_audit.py` (GNU probe
via WSL coreutils 9.4-oracle scratch `/tmp/winuxcmd-gate-qc`);
re-run after any command-lane change touching a noted behavior.

Driver provenance: `drivers: rust=D:\repo\wc-20inv\rust2\target\debug\winuxcmd-driver.exe; cpp=D:\repo\wc-20inv\rust2\..\build-vs\usr\bin\winuxcmd.exe; bash(setup)=C:\Users\cmx\AppData\Local\Programs\Niubash\winuxcmd\usr\bin\bash.EXE; gnu=WSL /usr/bin coreutils`

Lesson baked in (#1550): `false --help` returning 0 lived inside a
note row until manual wiring checks caught it. A note is not a
verdict; it is a debt with an audit date.

Verdicts: **UPGRADE-STRICT/EXIT** = Rust already matches GNU, the
row should gate again (promotion owned by the command lane);
**MASKED-DIVERGENCE** = the note masks a live Rust-vs-GNU
divergence — the exact #1550 failure class, fix it or re-justify
the registered deviation; **UNDOCUMENTED** = no registry entry in
`gate/note-registry.tsv`.
