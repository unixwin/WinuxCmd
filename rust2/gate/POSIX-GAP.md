## Fixture-inertness run (native rust side, 1595 cases)

Every case ran twice in the SAME scratch path (wiped between
runs, so cwd-printing commands see one cwd and state cannot
leak across runs): once without and once with the
shell-namespace fixture env (`qc_common.posix_fixture`). The
corpus carries no POSIX spellings, so unexpected diffs would
be fixture leakage. Sensitivities split into two classes:
**expected** — commands whose output legitimately follows the
env (env dumps, TMPDIR consumers, volume enumeration) — and
**unexpected**, which need a look before trusting any
posix-round verdict.
